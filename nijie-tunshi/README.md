# 霓界吞噬

AI 编排立体几何世界的即时动作策略吞噬游戏。玩家加载后立即操控发光圆球滚动，以冲刺、引力牵引和相位穿越改变路线，击破核心锚点并完成浑天仪跃迁。

## 本地运行

在仓库根目录执行：

```bash
npm install
npm run dev:nijie-tunshi
```

打开 <http://localhost:4175>。

## 操作

- `WASD` / 方向键：滚动
- `Space`：冲刺并撞碎标有 `DASH` 的晶板
- 按住 `E`：引力牵引（质量 12 解锁）
- `Shift`：相位穿越（质量 32 解锁）
- `P` / `Escape`：暂停

移动端使用左侧摇杆和右侧三枚能力按钮。游戏无需规划界面，加载后立即开始。

顶栏有一枚喇叭按钮，**默认静音** —— AudioContext 必须等用户手势才能起，与其在首帧被浏览器拒掉，
不如让开声这件事本身就是那个手势。

## 音效：为什么这一个不能照抄别的游戏

`src/scene/audio.js` 全部现场合成，不引音频文件。数据表和 `listen`／`cuesFor` 是纯的，
只有 `createAudio` 碰 `AudioContext` 且懒建 —— 静音状态下一个音频节点都不建。

难的地方不在合成，在**事件通道的形状**。仓库里其他几个游戏是回合制：一次动作吐一份 `effects`
数组，`notify(effects)` 放完就丢。这里是实时的，`simulation` 维护三条**带 id 的队列**
（`collectionEvents`／`stageUpEvents`／`actionEvents`，各封顶 48 条），每帧读到的是
「至今为止的尾巴」，不是「这一帧新增的」。照直喂给播放器，同一声会按帧率重放。

`createScene` 用三个 `Set` 去重。音频这边**没有照抄**：那三个 `Set` 一局下来只涨不消。
事件 id 是 `${type}-${eventCursor}`，而 `eventCursor` 在一局里单调递增 —— 所以记住
「听到第几号」就够了，O(1) 内存。这条水位线还白送了两件事：

- **换局自动重置**。新局 `eventCursor` 归零，一比就知道水位线作废了。换图、重开、进下一宇宙
  都不用额外通知音频层，`useEffect` 重建场景时音频照旧活着。
- **静音期间照样推进**。中途开声不会把攒下的几十个事件一起放出来。

三个还得自己判的取舍：

- **形态进阶和剧情推进会撞在同一帧。** 七个剧情阈值（0/12/22/32/60/90/130）里有六个跟
  `PLAYER_STAGES` 的形态阈值重合，各自出一声就是同帧双响。所以剧情声只在**没有形态进阶**时才出 ——
  唯一剩下的是质量 22 那一档「选甜味路线」，而它恰恰是最该被听见的：全局唯一一个要玩家做决定的节点。
  测试直接从两张表里算出重合数量，改了配方表会立刻炸。
- **一帧能同时吞下好几颗糖**（引力牵引会把一片糖屑一起拉进来）。按最大那颗定音色
  （`mass >= 8` 是 `chomp`，以下是 `bite`），数量差别交给连击音高，不放五声。
- **连击音高走五声音阶**（`PENTATONIC`），不是半音阶。连吃二十颗时半音阶听起来像警笛，
  五声音阶每一级都还在调里。

震动只给四个关口（通关／跃迁／爆发／进阶／掉稳定度），吃糖不震 —— 一局要吃上百颗。

## 验证

```bash
npm run test:nijie-tunshi
npm run build:nijie-tunshi
```

129 个测试。音效那 16 个用假 `AudioContext` 验的都是上面那些取舍，而不是「有没有出声」：
读两遍同一份 state 第二遍必须一声不出、换局水位线作废、进阶与剧情同帧只响一次、
`crossroads` 那一档必须响、一帧最多三声、限流跨帧才成立。

当前版本是固定种子核心原型。关卡配方和生成验证接口已在规划中，后续接入 AI 编排服务。
