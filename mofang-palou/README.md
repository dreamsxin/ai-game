# 魔方爬楼 · Cube Climb

无尽爬楼的三维推移解谜。一座塔就是一个 **N 阶魔方**：N×N×N 个砖格，从底层爬到顶层的出口。
通了一座就接下一座，阶数从**三阶爬到六阶**，六阶之后靠打乱步数继续加压。没有失败判定，
只有你能爬多高。

## 为什么是「魔方」

整行整列地推砖，本来就跟拧魔方是一回事 —— 只是魔方转的是面，这里推的是线。
关键在于：**一层的时候只有行和列；多层的时候就多出一个面的行和列**，那多出来的一族就是「柱」。

三维格子里，一条线只有三种取法，**不存在第四种**：

- 固定 `(layer, row)`，沿 col 走 → 推一整**行**
- 固定 `(layer, col)`，沿 row 走 → 推一整**列**
- 固定 `(col, row)`，沿 layer 走 → 推一整**柱**（砖在楼层之间上下搬）

所以扩展是封闭的：三条线族齐了，这个玩法的动作空间就到顶了。

一条线由**「锚点格 + 轴」**确定 —— 线上的格子跟锚点共享另外两维。三条轴共用同一套表达式，
`activeLayer` 只是视图状态，不参与动作。

## 视角就是轴选择器

这是这游戏最要紧的一个设计决定。三个视角：

- **俯视**：看当前一层。横滑推行，竖滑推列。
- **侧视**：看一道纵剖面。横滑推行，竖滑**推柱**。
- **转台**：看整座塔，只看不推。

**转到哪一面，滑动就推那一面的行列** —— 跟拧真魔方一样，先把要动的那面转到眼前。
于是不需要额外的「轴切换」按钮，也不用发明第三种手势（手机上双指和长按都会跟横滑竖滑打架）。
顺带解决了「柱推移把砖推进看不见的层」这个可见性问题：柱在侧视里是横着摆的一排，一眼看得全。

## 六个面，六扇门

一块砖是**六位门掩码**（`DOOR_N/E/S/W/U/D`）。相邻两格要**两头同时开门**才通，上下方向也一样 ——
所以楼层之间不需要「跃迁垫」之类的额外概念，上下就是普通的门，整座塔是一张真正的三维图。

一条有意的不对称：**推移会绕回，连通不会绕回**。掉出边界的砖从对面进来，但走位时最边上那块砖
的外侧门是墙。绕回让「推」有回旋余地，不绕回让「路」看得懂。

## 可解性是构造出来的，不是搜出来的

1. 在 N×N×N 上随机深度优先挖一棵**生成树** —— 任意两格必然连通，这是「解开态」；
2. 按 `loops` 概率再开一些额外的门，让路不止一条；
3. 从解开态开始随机推 `scramble` 次，得到初始态；
4. 把打乱序列**反过来、方向取反**，就是一条保底解法。

推移可逆（±1 互逆）是这条构造的唯一前提。所以「这座塔有解」跟搜索预算无关 ——
六阶分支数是 `6·36=216`，宽搜只搜得动一层，全靠这条构造顶着。

**起点和出口是在打乱之后才放的**，这一点很关键。早先的写法是把两头跟着一起打乱，结果它们经常
被推离底层／顶层，只能靠换 seed 重生成整座塔去碰 —— 实测平均要试 3.08 次，最坏 20 次，
400 次里还有 2 次彻底失败。改成先打乱、后放两头之后：

- 起点在底层、出口在顶层，变成**构造保证**的，一次都不用碰运气；
- 「开局不能已经通关」也是构造保证的：一次洪泛拿到某个起点的整个可达集，
  顶层里走不到的格子才能当出口；
- 解开态是挖通的，任意两格必然连通，所以「解开态里出口可达」是白送的，不用挑位置。

实测 400 座塔：**0 次失败，平均 1.055 次尝试，最坏 4 次**，唯一的拒绝原因是
「打乱之后底层到顶层处处都通，放不下两头」（400 次里 22 次）。

`par` 直接取保底解法长度，**不跑搜索**：为了一个更紧的 par 让每座塔多花几百毫秒不值得，
无尽模式要的是接得上。

## 难度与记分

- 阶数：`orderForTower(i) = min(6, 3 + ⌊i / 2⌋)` —— 同一阶连爬两座，一座学一座熟。
- 打乱步数：三阶 4 起步，六阶 14 起步；到六阶不再升阶，改成每多爬一座 +2，封顶 40。
  再深下去一座塔要磨十几分钟，无尽模式的节奏会断。
- 额外开门率：三阶 0.24 递减到六阶 0.1，越往上路越容易断。
- 记分：爬上去的楼层是主分，一座 N 阶塔算 N 层、给 `N×100`；步数不超过打乱步数再给 200。
- **走位免费，只有推移计步** —— 你付的代价是「改地形」，这是这个玩法的核心取舍。
- 撤销 40 步。累计步数不因撤销打折：撤销是给思考留余地，不是给成绩打折。

## 结构

`src/game/` 是纯逻辑层，不碰 DOM 也不碰 three：

- `rules.js` 六个门位、三条轴、阶数与打乱曲线、记分、视角与轴的对应
- `cube.js` 三维砖阵：连通、洪泛、最短路、三轴推移、局面指纹
- `generator.js` 挖树 + 加环 + 打乱 + 放两头 + 体检
- `solver.js` 动作全集、`applyShift`（砖阵／玩家／出口一起走）、有界宽搜
- `simulation.js` 回合制状态机，一次动作吐一份新状态，带一串 `effects`

## 测试

44 个测试，`node --test test/*.test.js`：

- `cube.test.js` 盯住三轴推移各改哪一维、绕回、可逆、「连通不绕回」这条不对称，
  以及指纹必须带出口（少这一维会把不同局面当成同一个剪掉）
- `generator.test.js` 核难度曲线单调、起点在底层出口在顶层、开局一定还没通、
  保底解法真的走通并把砖阵还原成解开态
- `simulation.test.js` 核记账（步数、历史、累计成绩跨塔带走）、推柱会把玩家和出口一起带上下楼、
  撤销把三样一起退回去、通关结算、没通不许跳塔、视角与轴的对应
