# AI 小游戏集合

每款游戏使用独立 workspace。需要对话或推理能力的游戏通过 MCP 工具接入 AI，实时 3D 游戏使用确定性规则保证操作响应。

## 进度总览

21 个游戏 + 3 张 3D 旅游导览图（`zhejiang-luxing`、`jiangxi-luxing`、`lishui-luxing`，见下）+ 2 张长卷（`qiannian-jiangshan` 千年江山图、`shici-jiangshan` 诗词江山图）。「关卡」一列区分三种结构：**闯关**有关卡表，**无尽/单局**用难度或阶段代替关卡，**生成器**用风格预设代替关卡。

闯关类合计 163 关（3 + 5 + 100 + 6 + 6 + 3 + 16 + 8 + 8 + 8）。其中迷宫穿越的 100 关由 `CHAPTERS` 端点插值生成，
难度曲线单调有测试守着；关卡本身由 seed 现场生成，所以同一关每次都是新图。
换翼计划的 16 关是手写波次表，但 Boss 血量由算式反推（推荐机翼的有效 DPS × 目标时长），
机器人通关测试守着「带对机翼过得去、带错机翼要付代价」这两条。
水弹堂的 8 关只有四个旋钮（柱阵排法、箱子密度、对手数量、对手档位），
关卡表本身有测试守着「对手数量和档位一路不降」，同一个大脑（skill=1）接管玩家跑完八关守着「每关都过得去」。
旋风卡丁的 8 关也是四个旋钮（弯道密度、路面宽度、圈数、对手档位），赛道中心线由极坐标谐波和生成，
所以「弯道密度」是一个可测的数：测试守着平均曲率一路走高、最紧的弯一路更紧。
它还多守一条别的游戏没有的东西——**玩法经济**：把玩家的手刹或氮气单独掐掉跑对照组，
八关都必须满足「漂移+喷 < 一路抓地 < 漂了不喷」，否则这游戏的核心循环就是假的。
铁血魂斗把这条对照组的做法抄了过去，守的是另一种经济：把**命中回弹**整局关掉，
同一个机器人打同一台 Boss 会慢 1.5～2.8 倍；把「往前压」掐掉则八关一关都打不完。
它的 8 关旋钮是兵力、炮台数、Boss 血量和地形垂直度，前三个都能从字符画里直接数出来。

- `zhejiang-luxing`：3D 浙江旅行地图《浙江旅行地图》，不是游戏而是导览工具——地形按「七山一水两分田」由高程控制点插值生成，37 个景点按经纬度落点，点标记就出**看点／游玩 tips／建议时长／最佳季节／门票形态／怎么到／顺路还有哪几处**；可按分区、类型、季节筛选，也能直接搜「云海」「日出」「海鲜」这类看点关键词；6 条推荐行程选中后整条线框进画面并画出缎带和站点编号。
- `tiexue-hundou`：手机触屏横版跑射《铁血魂斗》，魂斗罗式的八向射击与一击死，但**弹药只从命中里来**——枪是自动开火的，弹匣打空只能装回 5 发而且很慢，打中人回 1 发、打中 Boss 核心舱回 2 发、打在装甲上一发不回。所以「站远了扫射」是最先把自己饿死的打法。**蹲下会停火并快速换弹**，代价是蹲着不能动；捡到的散弹／机枪／激光死一次就掉回步枪，火力是一次投资。关末那台机器的核心舱开 2.4 秒、闭 1.5 秒，开着的时候弹幕也最密。八关递进的是压迫方式：兵力、炮台、Boss 血量和地形垂直度。
- `jiangxi-luxing`：3D 江西旅行地图《江西旅行地图》，同样是导览工具而不是游戏——江西是个三面环山、向北开口的盆地，所以这张图的骨架是**赣抚信饶修五条河汇进鄱阳湖、再从湖口流入长江**：水面按真实水位画，赣江在赣州还有约 100 米、到吴城入湖只剩 15 米，河谷因此是斜着往下走的；省界之外的邻省整块压低并调成灰蓝，绿色的那块就是江西。46 个景点按经纬度落点，点标记出**看点／游玩 tips／建议时长／最佳季节／门票形态／怎么到／顺路还有哪几处**；可按分区、类型（名山／湖江／古村／瓷都窑火／红色印记／人文古迹／山野秘境）、季节筛选，也能直接搜「晒秋」「云海」「候鸟」「柴窑」这类关键词；8 条推荐行程选中后画出缎带与站点编号。46 个景点加城市、山峰标注做了**屏幕空间避让**，全省视角下不会糊成一堵字墙。
- `lishui-luxing`：3D 丽水导览图《丽水山水图》，用《千里江山图》的矿物色画——**天不是蓝的**（画里的天是绢本身，所以天空与雾都用绢黄，远山淡入绢底就是留白），高程色带谷底绢黄赭石→山腰石绿→峰顶石青，景点名写在绢色题签上、类别与行程站序用朱砂印章。丽水「九山半水半分田」，水体各在不同海拔上（云和湖 184m、千峡湖 160m、南明湖 50m，瓯江从龙泉 190m 降到温溪 8m），所以**每处水面各记自己的高度**，一张海平面盖全图的做法在这里直接不成立；市界之外不裁断而是随距离退场成绢底留白。九县 37 处景点、7 个分类、6 条行程（瓯江山水诗路／剑瓷云山／松阳古村／云海梯田／畲乡廊桥／缙云仙都古村），能搜「云海」「廊桥」「青瓷」「梯田」。
- `qiannian-jiangshan`：2D 历史长卷《千年江山图》，同一套矿物色，但**画的是时间**——横轴从新石器到 1912 年，切成 25 段首尾相接的山峦，**每段的主峰高度精确等于它的国力值**（噪声只往下削），所以「唐前期 95、唐后期 50」在卷上就是一道断崖，「乱世的峰一定低于两侧的大一统」是一条有测试守着的硬规则。段不等于王朝：**国力断崖处要切开**（唐在安史之乱、清在鸦片战争各切两段，王莽的新朝从西汉里单列），否则一座山会把「盛极」和「续命」画成同一个高度；乱世段的谷口压到江面、铺上云雾，卷面就真的断成几截。横轴**分段线性**而非等比例（每段宽度由时长的 0.45 次方和手调 `weight` 共同决定），条目密的朝代靠加 `weight` 腾卷面。卷上 195 条：52 件事、89 个人（诸子百家儒道墨法名阴阳纵横兵杂各有其人）、54 部典籍，事件朱砂菱形、人物石青圆点、典籍藤黄方块，标注做**屏幕空间避让**并按年份往上叠行（x 由年份决定，一步也不许挪）。能按类型、标签筛，也能搜「兼爱」「白马非马」这类词。
- `shici-jiangshan`：3D 诗词地图《诗词江山图》，把丽水那套矿物色画法放到全国——**一枚印章管一处地方，不是一首诗**，唐宋元 406 首落在 127 处（玉门关到儋州、上京草原到岭南），印章的颜色是朝代、印文是主题，一处压着好几首时印章更大、点开先出这一处的清单（长安三十四首、杭州二十首、汴京十二首、洛阳与扬州各十一首）；诗名题签上写的是"地名 · N 首"，筛选之后数目会跟着改。归堆在判定层（`atlas/clusters.js`）：先按 0.12 度网格分，再把同名近邻并起来（格子边界会把长安切成两半），**分堆只取决于坐标、与数据表顺序无关**，所以印章 id 能直接当拾取标识；晕圈、杆与拾取体都是 `InstancedMesh`，印章要上到几百枚才不会被 draw call 拖死。条目从一百多首扩到一百七十多首时冒出一件只在密度上来后才看得见的事：**`place` 的首段就是这处地方的身份**，写成"长安市""长安里巷""长安南郊"会让长安散成三四枚印章，其中一枚还被邻近的乐游原抢了名字（于是《无题》的题签上写着"乐游原"），所以细部一律写在 `·` 之后（"长安·西市"），并由两条测试守着：**报同一个地名的诗必须落在同一枚印章上**、**一枚印章里的诗必须都报同一个首段**（否则印章刻谁的名字就成了众数碰运气——金陵那一枚曾因此刻着"石头城"）。这两条测试顺带翻出三处坐标错：《夏日绝句》的乌江偏了一百公里、《竹枝词》标夔州却落到一百四十公里外、《望天门山》挤进了乌江镇那一格。《静夜思》《锦瑟》这类**写作地历来无定说的，宁可不落点**（硬派一个地方就是编造），只进列表与检索；**落不下还有第二种理由 —— 地方认得出但在图幅之外**（这卷子西边止于玉门关一带，岑参的北庭、李颀的交河、王安石《明妃曲》的塞北毡城都在画外），两种都由同一条测试守着"必须在 place 里交代清楚"。放大到全国之后另有两件事必须重做：一是**色带不能一路加深**，横断山、青藏东缘一大片都在三千米以上，石青加深下去比海还暗、西半边会读成一片海湾，所以两千四以上改成越高越淡、最后淡进绢底（画里的"高则明、远则淡"），这条规则由 `atlas/palette.js` 的测试守着；二是**垂直夸张要按图幅重算**（省域图的 60 倍在这里会把秦岭拉成一百八十公里高，全图糊成一张皱铝箔，压到 30 倍）。一百多首一起写出题签就是一堵字墙，所以**全卷远看只出印章与古地名**，走近、点中、或那首诗在当前行迹上，诗名才铺开。数据按选集分册（`spots.js` 是最早那批，其后唐宋元各有 `spots-*-b/c.js`，末尾并成唯一的 `SPOTS`）；分批灌数据最容易犯的错是"同一首收了两遍、只是 id 起得不一样"，id 唯一性拦不住它，所以另有一条测试按"作者《篇名》"与正文前十四字各查一遍。元曲占 68 首，散曲的口气和唐诗宋词明显不同（睢景臣让一个乡下人把汉高祖的威仪拆了，萨都剌平视草原写乳酪和毡帘，无名氏《醉太平》张口就骂"堂堂大元"，卢挚与珠帘秀一赠一答成对收在扬州江上）。11 条行迹（李白／杜甫／王维／苏轼／白居易与江州／晚唐怅望／边塞一线／金陵怀古／南渡之路／南贬之路／元曲行路，共 155 站、覆盖 149 首），能搜作者、地名，也能搜诗句里的字。另有一张**作者星图**（判定层 `atlas/starmap.js` + 画法 `scene/starChart.js`）：146 位作者按收录篇数分六等星，一等最亮（李白 20、王维 17、苏轼 16、杜甫 15），六等是只收一首的七十八位 —— 柱状图会把这条长尾压成一排看不清的短线，而**星等本来就是给"差几十倍"的量准备的**；同朝的连成一条旋臂（石青唐、石绿宋、赭石元），点一颗星看这位写过哪些地方，再点一首回地图上读它。星位只取决于数据（名次并列按字符序断、抖动取名字的散列而不是随机数），所以每次打开都一样，"星点不许叠在一起""篇数越多越亮"两条由测试守着。做这张图踩了三个坑，都记在代码注释里：把星等表整个摊进星对象会让它自带的 name（"一等星"）覆盖掉作者名；收边（拉回圆盘）必须放在每一轮推挤里做，否则最后统一收会把刚推开的两颗又按回一起；"最小径向间距"只能压内圈，一路压到外缘会把七十八颗六等星逐个推到边上、连成一圈钢丝。星盘的大小**两个方向各自算**：第一版取短边画正圆，1920 宽的屏上只铺开三成七、左右各空一大片，与"宽屏没适配"是同一个毛病；现在两轴各吃满自己的边、再互相压一道 1.6 的椭圆上限 —— 到 2:1 以内的屏两向都铺开六成以上，21:9 上铺不满是有意的代价（要铺满就得扁成一条带，旋臂会糊成三条横线），星图的面板也跟着地图那层一起有 1600／2200 两档大屏尺寸。这几条由 `test/starChart.test.js` 守着。

## 打 Android APK

`migong-chuansuo` 和 `zhizhu-zhipai` 接了 Capacitor，原生工程分别在各自的 `android/`（已入版本库）。

```bash
$env:JAVA_HOME = "E:\apk\tools\jdk-21\jdk-21.0.5+11"   # 必须是 JDK 17–21
npm run apk:debug --workspace migong-chuansuo
npm run apk:debug --workspace zhizhu-zhipai
# 产物：<游戏>/android/app/build/outputs/apk/debug/app-debug.apk
```

两条最容易卡住的：**Android Studio 自带的 `jbr` 是 JDK 25，用不了**（Gradle 8.x 不支持 Java 25，
而 AGP 8.7 又还没跟上 Gradle 9），要另找一个 JDK 17–21；以及 `android/local.properties` 里的
`sdk.dir` 要指向本机 SDK（该文件按惯例不入库）。完整的坑位清单见
[`migong-chuansuo/README.md`](migong-chuansuo/README.md) 的「打 Android APK」一节。

实测体积：迷宫穿越 4.1 MB（带 Three.js），蜘蛛纸牌 3.90 MB（牌面是 DOM 真文字，前端零图片资源，
几乎就是 Capacitor 壳本身的体积）。两边的图标不一样：蜘蛛纸牌的启动图标是自己画的
vector（牌桌绿底 + 黑桃 + 背后一张蛛网），没有沿用 Android Studio 模板那套青绿方格底，
不然两个游戏装在同一台手机上，桌面会出现两个一模一样的图标。

要给别的游戏也打包，照 `migong-chuansuo` 抄三样东西：`vite.config.js` 里的 `base: './'`、
`capacitor.config.json`、以及 package.json 里的 `apk:*` 脚本，然后 `npx cap add android`。
