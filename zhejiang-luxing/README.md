# 浙江旅行地图 · Zhejiang Travel Atlas

一张可转、可缩、可点的 3D 浙江旅游导览图。地形按「七山一水两分田」的真实骨架生成，
37 个景点按经纬度落点，点开任一处就能看到**它在哪、主要看点是什么、有什么游玩 tips**。

```bash
npm run dev:zhejiang-luxing   # http://127.0.0.1:4196
```

## 怎么用

- **转/缩/平移**：左键拖动旋转，滚轮缩放，右键（或双指）平移
- **点标记**：弹出景点卡 —— 等级头衔、建议时长、最佳季节、门票形态、怎么到、看点、tips、顺路还有哪几处
- **筛选**：按分区（浙北／浙东／浙西／浙南／海岛）、按类型（湖光水色／古镇水乡／名山奇峰／海岛渔港／古迹人文／田园秘境／都市体验）、按季节，或直接搜看点关键词（「云海」「日出」「海鲜」都能搜到）
- **推荐行程**：6 条线路，选中后整条线框进画面并画出缎带与站点编号，站点可逐个点开
- **视角与时段**：全省／五个分区／正俯视，晨雾／正午／黄昏三套光照

## 分层

判定层（`src/atlas/`）没有 DOM 也没有 three，可以直接被 `node --test` 吃掉；
表现层（`src/scene/`）只读它、不改它。

- `atlas/spots.js` — 37 个景点的事实表：坐标、等级、时长、季节、看点、tips、交通
- `atlas/geo.js` — 地理底板：省界轮廓、14 处海岛、6 个湖、8 条水系、68 个高程控制点、11 个城市标注
- `atlas/terrain.js` — 高程场。反距离加权插值 + 两个八度噪声，再挖出海、湖、江
- `atlas/projection.js` — 经纬度 ↔ 场景坐标，经度乘 cos(中心纬度) 防止形状被拉扁
- `atlas/routes.js` / `atlas/query.js` — 行程表；筛选、搜索、统计、附近景点、行程展开
- `scene/atlasGroup.js` — 地形 mesh、水面、省界、标记、行程缎带、地名
- `scene/createScene.js` — 天空、光照、轨道控制、拾取、镜头飞行

## 三个值得知道的取舍

**水面只用一张。** 湖和江都被挖到海平面以下，然后由一张半透明水面统一盖住。
代价是「千岛湖其实在海拔 100 米上」这件事图上看不出来；换来的是水体连续、没有接缝，
而且千岛湖的岛、钱塘江的河道都是同一套高程场算出来的，不需要额外贴图。

**高程控制点必须成对给：山峰 + 河谷。** 只放山峰的话，反距离加权会把整个浙南插成一块连续高原，
山谷（人和公路真正待的地方）全被填平，画面上就是一大片惨白的高地 —— 这个坑踩过一次，
修法是把县城、盆地、河谷的真实低值也放进 `RELIEF`，并把插值指数提到 4 让影响局部化。

**标注是屏幕固定字号。** `sizeAttenuation = false`，所以拉远拉近字号不变。
按世界尺寸给字的话，全省视角下 37 个地名会小到看不见。密集处（杭嘉湖）再按序错开六档高度，
最挤的几处仍会轻微相叠，拉近一点就分开 —— 这是地图该有的行为，不是缺陷。

## 数据口径

坐标是景区主入口或标志景点的 WGS84 近似值，用于**定位**而不是导航。
门票和预约规则变得很快，所以 `ticket` 只写量级和规则形态（免费／分景区另收／登岛必须乘船），
不写具体金额；景点卡底部固定提醒出发前查官方渠道。等级只在确认是国家 5A 时才写 5A，
其余写世界遗产、国家级风景名胜区这类实称。

## 验证

```bash
npm run test:zhejiang-luxing
npm run build:zhejiang-luxing
```

37 条测试守四件事：

1. **每个景点都答得上问题** — 至少 2 条看点、2 条 tips，坐标在浙江范围内，分区／类别／月份合法，
   每个筛选选项都至少能选出一个景点（不会出现点了就空白的按钮）
2. **相对位置没摆错** — 普陀山在西湖以东、雁荡山在天台山以南这类常识
3. **地形骨架还在** — 西南山区 >800m 且浙北平原 <60m；海、湖、江各自被认出来；
   省界外的舟山群岛仍然是陆地；千岛湖里真的有岛
4. **行程是顺路的** — 相邻两站直线不超过 170km，全线不超过 600km，平均每天挪动 ≤110km，
   六条线合起来覆盖全部五个分区
