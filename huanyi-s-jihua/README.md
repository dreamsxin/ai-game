# 换翼S计划 · 2.5D 射击

手机触屏优先的纵版飞行射击闯关，`huanyi-jihua`（换翼计划）的 **2.5D 重画版**：
判定层一个字段没改，表现层整层换成 three.js 的斜俯视三维战场——固定俯角 58°、霓虹峡谷、
泛光弹道，战机、敌人、Boss、弹幕、地形全部程序生成，不含任何第三方素材。

玩法、数值、16 关的波次与 Boss 血量与 2D 版完全一致（同一套 `src/game/` 和同一份机器人测试），
所以这一份 README 只写**不一样的那一半：画面**。玩法请看 `huanyi-jihua/README.md`。

## 一分钟上手

- 屏幕任意位置按住拖动走位（相对拖动，手指不会盖住船），火力一直是自动开的。
- **轻点弃翼**：机翼原地脱落，主机获得 1.05 秒无敌并加速一截，但只剩威力最小的小炮。
- 带着翼被打中只掉翼，裸机被打中才掉命，共三条命；敌弹可以被打掉。
- 键盘：方向键或 `WASD` 走位，`Space`/`Z`/`X`/`J` 弃翼，`Esc`/`P` 暂停。
- 16 关四章，每章第一关可挑机翼，第 4n+2 关有跳关门，第 9 关起解锁五种实验机翼。
- 捡到同型号机翼升阶 Mk.I → Mk.III；**阶级跟着机翼走**，弃翼扔掉的是一整套投资。

## 触控：2.5D 的走位要按透视换算

相对拖动在 2D 版里很简单：像素位移除以「画布边长 / 场地边长」就行。2.5D 不行——
**一个像素等于几个场地格要看那一处有多远**，远处压得扁，同样一像素在那儿值更多格。
照平均值换算的后果是竖向拖动比手指慢四成（0.202 对船那一处真实的 0.325），
而且船越往画面上方越粘（场地 y=30 处真实值 0.501，差到 2.5 倍）——手感上就是「拖不动、跟不上」。

所以判定层的 `createInput` 留了一个 `scale` 注入口，表现层给它
`view.js` 里的 `pixelScale(aspect, width, height, shipY)`：按船**当前的深度**算横竖两个比例。
这份换算是纯函数，`view.test.js` 守三条：船那一处横竖比例一致（差 10% 以内）、
越远一个像素越值钱、以及它必须明显大于「场地高 / 画布高」那个平均值（正是第一版的错）。

手机上还有几条只有真机（或真派触摸事件）才看得见的：

- **`touch-action: none` 要写在真正被手指命中的那个元素上**：事件目标是 `<canvas>` 而不是它的父 div。
  整个操作层 `.app` 也关掉浏览器手势，只给要滚的浮层留 `pan-y`；弃翼键写 `none` 而不是
  `manipulation`（后者会把「按住再滑一点」判成滚动，浏览器随即发 `pointercancel`，按住的键自己松了）。
- **`lostpointercapture` 必须和 `pointerup` 走同一个结账函数**。它是手机上唯一能接住
  「长按被系统打断」的那一路，但 Chrome 里它可能排在 `pointerup` **之前**——
  当成「只是打断」直接销账，`pointerup` 就找不到这根手指，**轻点弃翼会整个失灵**。
  这个 bug 判定层测试全绿、只有真派触摸事件才抓得到。
- **切出页面时把按住的手指清账**（`clear()`），否则回来船会自己一直往一个方向走。
- **看不见的摇杆等于没有摇杆**：按住时画一圈光环，并连一条虚线到船身——
  那条线就是「相对拖动」这件事本身：手指不必压在船上。
- 轻点阈值按场地格算，而透视换算把每像素的格数抬高之后它的等效像素数会缩水，
  所以 `TAP_SLOP` 从 4 格提到 5.5 格（约 14 像素），免得按下时手指轻轻一滚就把弃翼吃掉。

**那个弃翼提示条为什么留着、又为什么不能点**：轻点画布任意处就能弃翼，可这是隐形操作——
这条胶囊是它唯一看得见的提示，还兼作状态显示（带翼「弃翼下潜」／裸机「无翼可弃」／「下潜中」）。
但它**不吃指针事件**（`pointer-events: none`）：走位是全屏拖动，一块会吞手势的按钮摆在拇指老家
就等于在最常按的地方开了个死区——从它上面起手拖动，船不动。关掉之后点它照样弃翼，
因为事件穿到画布上，而那本来就是「轻点即弃翼」。真机验证过两件事：
在它上面轻点会进下潜，从它上面起手拖动船会跟着走且不误弃翼。
（暂停与静音仍是真按钮，但它们在右上角，离拇指走位区很远。）

**布局是一列到底**：HUD、舞台、浮键共用同一个 `.frame`（限宽 560、居中）。
早先只给舞台限宽而 HUD 铺满整屏，宽屏上分数飞到屏幕最左、机翼飞到最右，和舞台完全脱节；
矮屏（高 ≤ 560）再把 HUD 的副标题收掉，别跟舞台抢高度。

## 2.5D 怎么摆

纵版射击里飞机其实是钉在屏幕上的，动的是世界。所以这一版把 100×150 的场地摊成地面，
相机架在近端上方往远处压 58°：**往屏幕上方走就是往远处走**，敌人从地平线那头压过来。

`src/scene/view.js` 是这件事的全部数学，而且**不 import three，所以能在 `node --test` 里跑**。
它守着两条否则只能靠肉眼发现的账：

- **整块场地必须全在画面里**。给定屏幕比例，`fitView()` 迭代解出相机该退多远，
  测试拿场地这只盒子的八个角逐个投影，八个角全在 NDC 之内、而且最远的角贴着边（不白白拉远）。
  从 0.46 到 2.2 八种屏幕比例各验一遍。
- **远处不许压得太扁**。俯角越平纵深越强，但远处的敌人也越小。
  `farNearScale()` 算出「同一个东西在最远端与最近端的屏幕大小之比」，测试把它夹在 0.5—0.85 之间：
  高于 0.85 是平面图，低于 0.5 是远处糊成一团像素。58°／58° 量出来约 0.7。

另外两条由同一份文件定死：`ALT` 是各类东西的飞行高度（贴地堡垒 1.4、战机 6、Boss 8.4），
所以「贴地的东西画得更低」有了具体的数；`BILLBOARD_X` 是正对镜头要转的角度——
相机固定，所以血条和文字只要绕 X 转一个常数，不用每帧做 billboard。

## 配色：色彩鲜明是可以断言的

四章各一套配色住在 `src/scene/palette.js`，由 `palette.test.js` 守着四条：

- **每章的亮色饱和度都在 0.55 以上**。这就是「色彩鲜明」的具体含义，不是形容词——
  灰蓝一片的星野看着"高级"，但四章会长得一模一样，玩家读不出自己推进到哪儿了。
- **底色够暗**（天顶亮度 < 0.12、地面 < 0.2，网格比地面亮 0.25 以上），亮色才浮得出来。
- **四章之间亮色色相互相拉开 40° 以上**：石青蓝 → 紫红 → 青绿 → 琥珀橙。
- **地形色一律避开敌弹那个红 30° 以上**。敌弹是全场唯一「碰到就掉翼」的东西，
  它的颜色不能和背景撞——所以第四章的葛布纳斯虽然是红色调，亮色走的是琥珀橙。

## 画面里的每一样东西都在说一件事

- **画面铺满窗口**，HUD 浮在它上面（限宽 720 居中）：竖版射击里纵向空间就是提前量，
  HUD 占一行等于把提前量削掉一截。宽屏上两侧不是黑边，而是峡谷岩体填满。
- **世界里一个字都不放**。斜俯视下道具约 20 像素、运载火箭约 30 像素、机身十几像素高，
  贴图文字缩到那个尺寸一定是一团糊的方块（128 贴图、加描边、抬到壳外都试过）。
  所以机翼阶级改用**三颗灯珠**，道具型号／火箭装的型号／跳关门的字全部由 2D 叠层
  按投影位置画成原生分辨率的字（`render.js` 的 `marks`）。
- **峡谷三层各跑一个速度**：地面栅格、栏上的刻度、两侧的岩体。飞机不动，速度感全在这三层。
- **战机是玄鸟**：乘波体机身加一层可拆的大后掠翼。有没有翼一眼看得出，因为带翼的机身明显更宽——
  那多出来的一截正是多出来的受击面积，而且 `models.test.js` 守着**画出来的翼展等于判定用的 12.8 格**。
- **两种无敌两种环**：挨打换来的是白环，弃翼换来的下潜是蓝环；机身闪烁而环常亮，
  所以还剩多久一眼看得出。下潜时另外拖一串半透明机身，这一串本身就是「现在打不到我」。
- **敌弹是亮红的球加一层光晕**，四章不变色。认颜色比认形状快。
- **我方火力是曳光弹**：细芯加光晕。第一版画成短粗的白方块，两路加农炮打出去像给跑道
  刷了两条车道线——所以侧栏刻度也跟着压暗了一档。
- **弱点环照 `weakSpots()` 摆**，所以「该往哪打」永远和判定一致；Boss 半血换姿态时
  外壳与正面那道光边一起转红。
- **菱形道具自己交代打不打得进本关弱点**：能打进的描一圈金环、型号写成金字或青字，
  不能的整枚压暗、型号压成灰字。
- **引力井画的是真实作用范围**（吸积环半径就是 `shot.well`），链弧是两点间抖六帧的折线，
  量子分身在镜像那一侧真有一具半透明机身在开火。
- **裸机时画面四边泛起会呼吸的红**。再挨一下就掉命，值得一个躲不开的提示。
- **泛光（UnrealBloom）**是这套霓虹画法的一半，但半径要压住：0.62 的半径下，
  Boss 那种又大又亮的实体会把整条天空糊成一块青绿。

中文飘字、全屏闪光、裸机红边走一层 2D 叠层画布（`.stage-overlay`）：文字用 canvas 比贴图清楚，
而且这三样本来就贴在屏幕上，不该有透视。

## 结构

`src/game/` 与 `huanyi-jihua` 逐字节相同：`rules.js` 场地与计分，`wings.js` 十五种机翼与三阶进化，
`levels.js` 16 关波次与 Boss（血量由算式反推），`enemies.js`／`boss.js` 行为，
`simulation.js` 固定步长状态机，`input.js` 归一化输入，`random.js` 确定性随机。
`test/` 也照抄，包括那个「会躲、会捡翅膀、会按弱点站位」的机器人跑完 16 关的 `playthrough.test.js`。

`src/scene/` 是换掉的那一层：

- `view.js`：取景数学与高度表，纯函数，`view.test.js` 守着。
- `palette.js`：四章配色、威胁色、阶级色，纯数据，`palette.test.js` 守着。
- `models.js`：程序生成的模型工厂（玄鸟机身与可拆机翼、六种敌人、Boss、道具、跳关门、各种弹）与对象池。
  **这一份里没有任何文字**，也因此有 `models.test.js` 守着「翼展等于判定用的 12.8 格」
  「带翼明显比裸机宽」「镜像／翻面的部件一律双面」。
- `stage.js`：相机、灯、天幕、地面栅格、侧栏、岩体、星野、泛光与震屏。
- `render.js`：把状态摆上舞台的总线，外加那层 2D 叠层（飘字、世界锚定的字、闪光、裸机红边、拖动指示）。
- `audio.js`／`readout.js`：与 2D 版共用同一套（音效仍全部由 WebAudio 现场合成）。

判定层之外还有两份「接线」测试，补的是判定层测试盖不住、而这一版真的栽过的那类失败：

- `wiring.test.js`：把**每个模块都 import 一遍**（重复声明、坏 import、模块作用域的 TDZ 在 `npm test` 就红——
  表现层模块一挂，面板照样能点但世界不动，症状是「黑屏 + 选了机翼没动作」），
  再照 `App.jsx` 的循环在 node 里跑一遍「出击 → 选翼 → 推进 4 秒」，断言世界真的动了。
- `models.test.js`：模型是程序生成的，所以能在 node 里造出来量，见上。

表现层只读模拟状态，一个字段都不写回，所以确定性回放仍然成立：
同一关加同一串输入，模拟结果逐字段一致，判定层的测试不需要浏览器。

**验收表现层只能开浏览器，但有个坑**：无头 Chromium 里原生 `requestAnimationFrame` 实测 **0 帧**
（量帧率那句 `evaluate` 会直接超时），所以拿真实 rAF 截出来的「黑屏」是环境造成的假象。
可行的两套办法：`addInitScript` 把 rAF 换成手动队列并暴露 `window.__flush(steps, dtMs)`（确定性、快），
或者换成 `setTimeout(16)` 的连续循环（按真实时间推进，能抓到「跑几十帧之后才抛」的错）。
