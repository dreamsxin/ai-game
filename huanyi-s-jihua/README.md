# 换翼S计划 · 2.5D 射击

手机触屏优先的纵版飞行射击闯关，`huanyi-jihua`（换翼计划）的 **2.5D 重画版**：
判定层一个字段没改，表现层整层换成 three.js 的斜俯视三维战场——固定俯角 58°、霓虹峡谷、
泛光弹道，战机、敌人、Boss、弹幕、地形全部程序生成，不含任何第三方素材。

关卡波次、Boss 血量与 16 关的结构沿用 2D 版（同一套 `src/game/` 和同一份机器人测试），
但**机翼表与同频共振这一层已经分叉**：这一版是常规 15 + 实验 5 + 隐藏 1，
升阶还会放相位冲击、开过载。
所以这一份 README 既写**重画的那一半：画面**，也写**这一版独有的设定与玩法**；基础规则与 2D 同源。

## 一分钟上手

- 屏幕任意位置按住拖动走位（相对拖动，手指不会盖住船），火力一直是自动开的。
- **轻点弃翼**：机翼原地脱落，主机获得 1.05 秒无敌并加速一截，但只剩威力最小的小炮。
- 带着翼被打中只掉翼，裸机被打中才掉命，共三条命；敌弹可以被打掉。
- 键盘：方向键或 `WASD` 走位，`Space`/`Z`/`X`/`J` 弃翼，`Esc`/`P` 暂停，`R` 重开（暂停/结算时），`M` 静音。
  触屏与键盘两套操作提示按指针类型自动切换。
- 暂停面板里有「重新开始」：打错了机翼、来了个电话，都不必先送光三条命才能重开。
- 16 关四章，每章第一关可挑机翼（常规 15 种，第 9 关起再解锁 5 种实验机翼 = 20 种，
  另有 1 型隐藏机翼），第 4n+2 关有跳关门。
  21 型机翼一型一条轮廓、一型一种颜色，选翼列表上每张卡片画的就是那只机翼真正的外形。
- **僚机是第二槽**：选翼面板同一屏可先带一型，关内打掉运载火箭也会掉六边形收纳舱。
  同型号合流到 3 架，编队挂在机身后方、自动开火并在近身蹭掉敌弹；
  裸机挨致命一击时替你挡一下（消耗一架），掉命则编队掉一级。
- **环形护翼三型（护环 / 远环 / 铁球）**：铁球绕着主机转，撞上来的敌弹会被蹭掉并计入连消——
  它们换来的是生存，正面火力都压得很低。三型的区别在环本身：贴身快转、大环慢转、折中。
- **同频共振**：只有捡到**同型号**机翼才升阶（为什么只有同型号，见下节），
  Mk.I → Mk.III 四个轴一起涨：**伤害 1.5 / 2.25 倍、冷却 0.82 / 0.7 倍、
  射程（弹丸寿命）1.4 / 1.9 倍、特殊弹作用范围（爆圈／跳距／井口）1.4 / 1.9 倍**——
  短程机翼（防卫炮、霰弹、火焰）升阶后不再贴脸才有输出，范围类机翼的圈也真的大一圈。
- 叠上的那一瞬间放一圈 **相位冲击**：震碎半径 26 格内的敌弹（照样计入连消、给分、出声），
  并给 0.7 秒无敌——「去接那只同型号翼」是一次有战术收益的动作，不是顺路捡个道具。
- 满阶之后再捡同型号不再是空捡：换成 5.5 秒 **相位过载**（伤害 ×1.35、冷却 ×0.8、
  射程／范围 ×1.15），阶级仍封顶在 Mk.III。过载是临时的，弃翼／换翼／掉翼一律清零。
- **阶级跟着机翼走**，弃翼扔掉的是一整套投资。
  不变量照旧：pierce / ground / 横向速度一个不碰，进化不能把选错的机翼变成对的。

## 设定：同频共振协议

机翼不是可以随便插拔的一把枪，是一副**带相位编码的翼面**。
两副翼面的编码一致，贴上的那一刻第二副才会被解构成「能量骨架」，回注进第一副——
所以场上那副道具会消失，机上那副会**展开**：升阶既是火力升级，也是一次外形变形。
不同型号编码不兼容，只能换装，阶级从 Mk.I 重来。这就把「为什么只有同种能升阶」
从一条规则变成了这套世界观自己的物理。

| 阶级 | 代号 | 设定名 | 场上发生什么 |
| --- | --- | --- | --- |
| Mk.I | `PRIME` | 原型构型 | 单副翼面，按出厂相位输出 |
| Mk.II | `SYNC` | 同频同步 | 第二副解构为相位骨架；火力 +50%、射程／范围 +40%、冷却 −18% |
| Mk.III | `RESONANCE` | 相位共振 | 三重翼场共振、翼面完全展开；火力 +125%、射程／范围 +90%、冷却 −30% |
| 限时 | `OVERDRIVE` | 相位过载 | 满阶后再叠同型号；5.5 秒内火力再 ×1.35，全场结构换白青 |

三阶的代号、设定名与收益全部写在 `wings.js` 的 `TIERS`，
`readout.js` 的 `tierGainLabel()` 从同一份数字现算百分比——
界面说「火力 +125%」而表里其实只涨 35%，是最难查的一种骗人。

这套协议没有动原来的三根柱子：机翼仍是装甲（带翼挨打只掉翼）、弃翼仍换无敌、
弱点仍由火力**性质**而不是数值决定。升阶只改「这一套火力打得多重、多远、多宽」，
不会把选错的机翼变成对的。

## 触控：2.5D 的走位要按透视换算

相对拖动在 2D 版里很简单：像素位移除以「画布边长 / 场地边长」就行。2.5D 不行——
**一个像素等于几个场地格要看那一处有多远**，远处压得扁，同样一像素在那儿值更多格。
照平均值换算的后果是竖向拖动比手指慢四成（0.202 对船那一处真实的 0.325），
而且船越往画面上方越粘（场地 y=30 处真实值 0.501，差到 2.5 倍）——手感上就是「拖不动、跟不上」。

所以判定层的 `createInput` 留了一个 `scale` 注入口，表现层给它
`view.js` 里的 `pixelScale(aspect, width, height, shipY)`：按船**当前的深度**算横竖两个比例。
这份换算是纯函数，`view.test.js` 守三条：船那一处横竖比例一致（差 10% 以内）、
越远一个像素越值钱、以及它必须明显大于「场地高 / 画布高」那个平均值（正是第一版的错）。

手机上还有几条只有真机（或真派触摸事件）才看得见的：

- **`touch-action: none` 要写在真正被手指命中的那个元素上**：事件目标是 `<canvas>` 而不是它的父 div。
  整个操作层 `.app` 也关掉浏览器手势，只给要滚的浮层留 `pan-y`；弃翼键写 `none` 而不是
  `manipulation`（后者会把「按住再滑一点」判成滚动，浏览器随即发 `pointercancel`，按住的键自己松了）。
- **`lostpointercapture` 必须和 `pointerup` 走同一个结账函数**。它是手机上唯一能接住
  「长按被系统打断」的那一路，但 Chrome 里它可能排在 `pointerup` **之前**——
  当成「只是打断」直接销账，`pointerup` 就找不到这根手指，**轻点弃翼会整个失灵**。
  这个 bug 判定层测试全绿、只有真派触摸事件才抓得到。
- **切出页面时把按住的手指清账**（`clear()`），否则回来船会自己一直往一个方向走。
- **看不见的摇杆等于没有摇杆**：按住时画一圈光环，并连一条虚线到船身——
  那条线就是「相对拖动」这件事本身：手指不必压在船上。
- 轻点阈值按场地格算，而透视换算把每像素的格数抬高之后它的等效像素数会缩水，
  所以 `TAP_SLOP` 从 4 格提到 5.5 格（约 14 像素），免得按下时手指轻轻一滚就把弃翼吃掉。

**弃翼动作键为什么长得像按钮、却不能点**：轻点画布任意处就能弃翼，可这是隐形操作——
右下角那枚大圆钮是它唯一看得见的入口，兼作状态显示（`jettisonKey`：可按「无敌 1s」金色发亮／
刚接上「锁定中」蓝灰／裸机「无翼可弃」虚线压灰／「下潜 x.xs」蓝色脉动）。
照手游的规矩它摆在右下拇指老家，但它**不吃指针事件**（`pointer-events: none`）：
走位是全屏拖动，一块会吞手势的按钮摆在拇指老家就等于在最常按的地方开了个死区——
从它上面起手拖动，船不动。关掉之后点它照样弃翼，因为事件穿到画布上，
而那本来就是「轻点即弃翼」。真机验证过两件事：在它上面轻点会进下潜，
从它上面起手拖动船会跟着走且不误弃翼。
（暂停与静音是真按钮，在右上角 44px——指尖的及格线——离拇指走位区很远，按下会瘪一下。）

**触屏和键盘是两套母语**：提示按 `matchMedia('(pointer: coarse)')` 切换——
触屏教拖和点，键盘教键位（标题面板与暂停面板各一份）；暂停与静音还有 `M` 静音、
`R` 重开（只在暂停和结算时接手，打起来误按 R 太贵）。

**布局是一列到底**：HUD、舞台、浮键共用同一个 `.frame`（限宽 560、居中）。
早先只给舞台限宽而 HUD 铺满整屏，宽屏上分数飞到屏幕最左、机翼飞到最右，和舞台完全脱节；
矮屏（高 ≤ 560）再把 HUD 的副标题收掉，别跟舞台抢高度。

## 2.5D 怎么摆

纵版射击里飞机其实是钉在屏幕上的，动的是世界。所以这一版把 100×150 的场地摊成地面，
相机架在近端上方往远处压 58°：**往屏幕上方走就是往远处走**，敌人从地平线那头压过来。

`src/scene/view.js` 是这件事的全部数学，而且**不 import three，所以能在 `node --test` 里跑**。
它守着两条否则只能靠肉眼发现的账：

- **整块场地必须全在画面里**。给定屏幕比例，`fitView()` 迭代解出相机该退多远，
  测试拿场地这只盒子的八个角逐个投影，八个角全在 NDC 之内、而且最远的角贴着边（不白白拉远）。
  从 0.46 到 2.2 八种屏幕比例各验一遍。
- **远处不许压得太扁**。俯角越平纵深越强，但远处的敌人也越小。
  `farNearScale()` 算出「同一个东西在最远端与最近端的屏幕大小之比」，测试把它夹在 0.5—0.85 之间：
  高于 0.85 是平面图，低于 0.5 是远处糊成一团像素。58°／58° 量出来约 0.7。

另外两条由同一份文件定死：`ALT` 是各类东西的飞行高度（贴地堡垒 1.4、战机 6、Boss 8.4），
所以「贴地的东西画得更低」有了具体的数；`BILLBOARD_X` 是正对镜头要转的角度——
相机固定，所以血条和文字只要绕 X 转一个常数，不用每帧做 billboard。

## 配色：色彩鲜明是可以断言的

四章各一套配色住在 `src/scene/palette.js`，由 `palette.test.js` 守着四条：

- **每章的亮色饱和度都在 0.55 以上**。这就是「色彩鲜明」的具体含义，不是形容词——
  灰蓝一片的星野看着"高级"，但四章会长得一模一样，玩家读不出自己推进到哪儿了。
- **底色够暗**（天顶亮度 < 0.12、地面 < 0.2，网格比地面亮 0.25 以上），亮色才浮得出来。
- **四章之间亮色色相互相拉开 40° 以上**：石青蓝 → 紫红 → 青绿 → 琥珀橙。
- **地形色一律避开敌弹那个红 30° 以上**。敌弹是全场唯一「碰到就掉翼」的东西，
  它的颜色不能和背景撞——所以第四章的葛布纳斯虽然是红色调，亮色走的是琥珀橙。

### 机翼：21 个色相，一型一色

章节配色管「打到第几章」，机翼配色管「手上这副是哪一型」。上一版只按出身分三色
（常规钢蓝 / 实验紫 / 秘密金），常规那 15 型在场上全是同一片蓝——换了翼只有炮管数变了。
现在 `WING_HUES` 一型一个色相，按「怎么打」排成一圈：暖橙是对地／火焰、黄绿是穿甲、
青绿是护环、冰蓝是直射、靛紫到品红是实验系，金黄留给秘密机翼。
`skinAt(hue)` 从同一个色相算出四个色阶（暗翼面 / 亮前缘 / 高亮识别色 / 近白金属炮管），
所以三维机翼和选翼小图拿到的是同一串十六进制字符串，不会「挑的时候是紫的、飞起来是蓝的」。
三维翼面、后缘灯带、翼尖航灯、炮口闪光、小图的前缘灯与翼尖灯珠都改吃这一份皮。
`palette.test.js` 守着：21 型 21 个色相、两两差 ≥ 11°、谁都离敌弹的红 > 18°，
外加 HSL → 十六进制 → HSL 的往返，以及翼面够暗、识别色够亮够饱和、炮管够白。

## 画面里的每一样东西都在说一件事

- **画面铺满窗口**，HUD 浮在它上面（限宽 720 居中）：竖版射击里纵向空间就是提前量，
  HUD 占一行等于把提前量削掉一截。宽屏上两侧不是黑边，而是峡谷岩体填满。
- **世界里一个字都不放**。斜俯视下道具约 20 像素、运载火箭约 30 像素、机身十几像素高，
  贴图文字缩到那个尺寸一定是一团糊的方块（128 贴图、加描边、抬到壳外都试过）。
  所以机翼阶级改用**三颗灯珠**，道具型号／火箭装的型号／跳关门的字全部由 2D 叠层
  按投影位置画成原生分辨率的字（`render.js` 的 `marks`）。
- **峡谷三层各跑一个速度**：地面栅格、栏上的刻度、两侧的岩体。飞机不动，速度感全在这三层。
- **升阶是一次变形，不是换色**（`models.js` 的 `makePhaseFrame()` + `render.js` 的相位翼场同步）：
  收到 evolve 事件后 0.55 秒内，整层能量场从 35% 展开到 100%。
  Mk.II 亮起一道贴地能量导轨、左右两枚悬浮棱晶与斜撑、翼面中央一条共鸣导线，
  **两片半透明能量翼只展开内半段**；Mk.III 能量翼整片张开、六根翼肋全亮，
  再架第二道外环、两道交叉倾斜的陀螺环、导轨上公转的八颗能量节点和机背共振核心，
  翼面三条导线全亮，两道弧环反向全开、机体大一圈。过载时全套换成白青、转速翻倍。
  能量翼刻意做成半透明、抬在实体翼上方两格、带发光骨架——它是**场**，不是装甲，
  玩家不会拿它当判定宽度（`makeWing` 里那 12.8 格一个字段没动）。
  自审截图里第一版把导轨管径给了 0.1，手机上只剩一圈一像素的虚线；
  第二版把整层结构全染成阶级暖金，加色混叠后糊成一团金光、形状反而没了。
  现在的管径、棱晶与光晕都是照「缩到二十像素还看得出形状」重调过的，
  配色也分了三路：**阶级弧环暖金、能量骨架冷青白、棱晶与核心纯白**。
  弹体按阶变粗并套一层发光能量鞘，尾焰随阶拉长，翼尖辉光更烈；
  HUD 底下另有一条只占 20px 的共鸣条（三格灯珠＝三阶，过载时白青脉动）。
  能量场单独挂在机体上、**不进 `makeWing`**：翼展 12.8 格是判定用的数，
  再科幻也不能把「看到的宽度」变成另一个数（`models.test.js` 守着这条）。
- **升阶那一圈冲击波画的是真实作用半径**：`evolve` 事件带着 `radius: SYNC_BURST_R`，
  表现层不自己编一个好看的数字；圈扩到哪儿，哪儿的敌弹就被震碎。
  脱手飘在场上那副翼也按自己的阶级亮着共鸣导线——「捡回来是第几阶」看得到。
  飘字同时报代号、设定名与从 `TIERS` 现算的收益，不是一句干巴巴的「Mk.II」。
- **战机是玄鸟**：乘波体机身加一层可拆的大后掠翼。有没有翼一眼看得出，因为带翼的机身明显更宽——
  那多出来的一截正是多出来的受击面积，而且 `models.test.js` 守着**画出来的翼展等于判定用的 12.8 格**。
- **每一型机翼都是从它的火力配置里长出来的**：`makeWing(code)` 照 `wings.js` 的 `volley`
  一发一个炮口摆上去，朝向就是那一发真正的方向——五路扇形真的是五根朝外的管子，前后炮
  真有一根朝后的，对地机翼的炸弹挂在后缘挂架上，环形护翼有吊篮，引力井有发射环。
  **轮廓不再按「族」查表，而是一型一条**：`WING_OUTLINES` 里 21 型 21 条（护环圆而短、
  远环窄而长、挂架翼后缘开挂架口、针翼薄得像刀、扇形翼带缺口、秘密机翼是双折角箭形），
  `WING_TRIM` 再给每型配一件只属于它的翼尖装置（小翼 / 刀片 / 鸭翼 / 吊舱 / 立尾 /
  撞角 / 边条）——斜俯视下翼面是块扁板，翼尖是轮廓上最容易被眼睛抓住的地方。
  族名 `WING_FAMILY` 只留给文档与测试，用来反查「这条轮廓配不配得上它的火力」。
  **颜色也是一型一种**：`WING_HUES` 给 21 型各一个色相，从火焰的橙红绕到量子的粉紫，
  两两至少差 11°、谁都不许掉进敌弹那个红区（见下节）。玩家两次报的都是「机翼都一样」，
  一型一形、一型一色就是那个反馈的答案。
  翼展永远是判定用的 12.8 格（`wingIcon.test.js` 守着每条轮廓的翼尖都钉在 6.4，
  翼尖装置全部收在 |x| ≤ 6.45 内）。
  - **`dx` 必须放大**：判定层的出膛横偏只有 ±1～3 格，照抄会让五根管子全挤在座舱底下，
    于是「2 路」和「5 路」画出来一模一样（玩家原话：换了机翼外形没变）。统一放大到
    最外侧约 ±4.6 格，左右对称与相对次序都保住，`models.test.js` 守着这两条。
  - **翼面要比机身暗、炮管要比机身亮**。第一版把翼面也点到接近白，几路火力全糊成一片。
- **选翼列表上画的就是机翼本身**：每张卡片顶上那张小图由 `scene/wingIcon.js` 从这只机翼真正的
  火力配置算出来（几根管子、扇形张多宽、炸不炸地、有没有吊篮／发射环／棱镜／线圈），
  和场上那副三维机翼取的是同一份数字——所以「挑的时候看到的」就是「飞起来带的」。
  翼弦、炮口横向位置、炮管长短只在 `wingIcon.js` 算一次，两边都从那里取；
  各算一遍必然分叉，而分叉的那一刻界面就开始骗人。
  - 顺手抓到一个真 bug：引力井的井口与链弧的跳数写在**那一发子弹**上而不是机翼记录上，
    第一版按 `spec.well` 找，这两件招牌零件从来没被画出来过（现在由 `wingTraits` 统一判定）。
- **弃翼扔出去的就是那副机翼本身**：道具不再是一枚抽象的菱形宝石，而是整副翼在翻滚。
  刚脱手那 0.42 秒抬一把再落回来、转得飞快，之后转速降下来平着飘——「抛出去」才有手感。
  能打进本关弱点的描一圈金环、型号写成金字或青字，不能的整副压暗、型号压成灰字
  （压暗是可还原的，同一副翼会在场上被反复压暗和点亮）。
- **两种无敌两种环**：挨打换来的是白环，弃翼换来的下潜是蓝环；机身闪烁而环常亮，
  所以还剩多久一眼看得出。下潜时另外拖一串半透明机身，这一串本身就是「现在打不到我」。
- **敌弹是亮红的球加一层光晕**，四章不变色。认颜色比认形状快。
- **冲击波环**：击杀、反物质炸开、掉翼、掉命、进化都往外扩一圈贴着爆炸高度的光环，
  快出慢收——「这里刚炸过」要有一个会扩散的形状，光靠火花太碎。
- **Boss 入场有一拍 WARNING**：红边脉冲加中央闪烁的大字（1.7 秒自退）。
  Boss 从地平线压过来需要几秒，这一拍先把玩家的眼睛叫到屏幕上方。
- **Boss 的死是一场演出，不是一次结算**（这一幕在判定层，`simulation.js` 的 `dying` 段）：
  血量归零进入 1.3 秒过载——场上它打出的弹幕全部原地炸成青白火花（清屏是礼节，
  不给分），壳体按固定节奏炸开（`bossBlast`，抖动走 rng，回放可复现）、外壳烧白发抖下沉、
  弱点环收掉，1.3 秒后才给 BOSS_SCORE 和过关和弦。轰完一整秒再「关卡完成」，
  比血条一空就弹面板有分量得多。
- **引擎一直往后喷余烬**：飞机钉在屏幕上，速度感一半靠地面三层，一半靠这些
  往近处跑的粒子；下潜时一帧三粒，「加速」看得见。
- **下潜时四边放射速度线**（`prefers-reduced-motion` 下省掉）：世界在后退，
  这一下「冲出去」的感觉值得几十条短线。
- **场上的一次性事件都要出声出字**：跳关门开了会顶一条横幅（「撞进去省 4 关（Boss 不会削弱）」，
  这个说明原本只写在 README 里，玩家在局里根本看不到）加两记钟声；自己弃掉的翅膀飘出画面
  （`lost`）、运载火箭带着机翼溜出画面（`escaped`）各有一条飘字加一声短音——
  「投资清零」和「这关的机翼呢？」不该是无声的。这三件都只出声不震动：弃翼和掉翼
  在发生的那一刻已经震过了。
- **我方火力是多层曳光弹**：白芯、色壳、外层光晕、头部闪光四层，并朝自己的速度方向转身。
  第一版画成短粗的白方块，两路加农炮打出去像给跑道刷了两条车道线——所以侧栏刻度
  也跟着压暗了一档；第二版拉长了但仍是竖杠，扇形散射读不出来。
- **弱点环照 `weakSpots()` 摆**，所以「该往哪打」永远和判定一致；Boss 半血换姿态时
  外壳与正面那道光边一起转红。
- **引力井画的是真实作用范围**（吸积环半径就是 `shot.well`），链弧是两点间抖六帧的折线，
  量子分身在镜像那一侧真有一具半透明机身在开火。
- **裸机时画面四边泛起会呼吸的红**。再挨一下就掉命，值得一个躲不开的提示。
- **泛光（UnrealBloom）**是这套霓虹画法的一半，但半径要压住：0.62 的半径下，
  Boss 那种又大又亮的实体会把整条天空糊成一块青绿。

中文飘字、全屏闪光、裸机红边走一层 2D 叠层画布（`.stage-overlay`）：文字用 canvas 比贴图清楚，
而且这三样本来就贴在屏幕上，不该有透视。

## 这一版重做的外形与弹道

沿用「所有东西都程序生成」，但把机体、机翼、子弹三层都往科幻推了一档，
并且把之前一直存在的一处过曝修掉了。

- **机体**：加了背脊与脊上那条能量缝、两侧肩部装甲板（各带描边）、翼根进气缝、
  机首传感器（小棱体 + 光晕）。上一版机身是一块扁板，斜俯视下没有厚度；
  这几件都压在 \|x\| ≤ 1.7 内，动不到「裸机有多宽」——那条宽度是判定的另一半。
- **发动机**：每个喷口从「一个锥体」变成三层羽流（柔和外焰、主焰、白芯）加一圈辉光环，
  各自抖不同频率，喷口环随推力一张一缩。静止的三条蓝线读不出「在推」。
- **机翼**：沿翼型后缘逐段铺灯带（跟着扇形翼的缺口、挂架翼的两块挂架走）、
  翼尖补两盏错相位呼吸的航灯、**每一路火力各一枚独立材质的炮口闪光**。
  枪口焰按 `ship.cool / wing.cool` 衰减——冷却刚重置那一瞬正好是开火，
  于是五路扇形能看出是哪一路在打。
- **子弹**：每种火力都改成多层（实心芯 + 色壳 + 外层光晕 + 头部闪光）。
  曳光弹按**自己的速度方向**转身，所以宽幅炮打出来真的是五路扇形，
  而不是五条平行竖杠。
- **激光**：`L` 的光束长度给到 30 格。它 0.05 秒一发、速度 190，相邻两发只隔 9.5 格，
  于是十几条首尾相接成一根连续光柱——**激光像激光，靠的是重叠，不是贴图**。
  三层同轴（外青晕、中层、白芯）加头部光团，`visuals.test.js` 断言长度盖得住间距。
- **修掉一处一直存在的过曝**：翼尖灯条是**不透明**的实体材质，自发光给到 3.5 时
  在屏幕上就是两团纯白光斑，把翼根糊掉。现在是 0.34 截面 + 1.4 上限的细金条。
  同一个坑还有三处：棱晶本体 0.9 的白色加色、共鸣导线埋在翼面实体里（等于没画）、
  无敌闪烁把 0.3 的柔和羽流一律拉到 1（越挨打飞机越亮）。
  后两条的修法是「材质标记 `driven`，闪烁跳过每帧自己驱动的那批」。

这几件事都有测试守着，而且守的是**会骗人的那部分**：
翼尖光晕不许越出 12.8 格（`Box3` 会把 Sprite 算进去，实测才发现）、
激光长度必须盖住相邻两发、每种弹至少三层、每一路非炸弹火力都有自己的闪光。

## 机翼：一型一形、一型一色

整体重画之后玩家又提了一次「不同的机翼颜色和外形都要不一样」。这一轮只动表现层
（`palette.js` / `wingIcon.js` / `models.js` / `App.jsx`），判定层一个字段没碰，
并且把「不一样」拆成三件可以断言的事：

- **21 型 21 条轮廓**（`WING_OUTLINES`）：从「按族查表的八种轮廓」改成一型一条。
  同族也不再共用——护环是短圆翼、远环是窄长翼、铁球翼带球座凹口；
  穿甲最长最薄、激光薄得像刀、引力井针翼带一个鼓包；破地两道挂架口、对地一道深挂架；
  秘密机翼是双折角箭形。翼弦倍率只拉纵深，翼尖一律钉在 x = 6.4。
- **21 型 21 件翼尖装置**（`WING_TRIM`）：小翼 / 刀片 / 鸭翼 / 吊舱 / 立尾 / 撞角 / 边条。
  三型留 `none` 是刻意的：排炮、破地、对地靠翼型和挂架就够，再加零件反而乱。
- **21 型 21 个色相**（`WING_HUES` → `WING_SKINS`）：见「配色」那一节。
  小图里原本写死的 `TIER_COLOR[0]` 翼尖灯珠也换成了这一型的识别色。

上一版「八种轮廓」的毛病是**族内共享**：常规 15 型里三四型共用一条三角翼，
换翼只变炮管数，于是「机翼都一样」反馈了两次。现在族名退化成文档与测试用的标签，
再不由它查表取形状。

验证分两步：先做一张 21 格图鉴（每格单独摆相机、用与游戏同角的斜俯视渲染一次），
一屏看完全部轮廓与颜色；再用无头 Chrome + CDP 进游戏实拍选翼面板与开局，
确认场上那副翼的颜色和小图一致、左右对称、没有过曝白斑。
`npm test` 280 条断言里，`models.test.js` 守「21 型颜色两两不同 / 21 份翼面几何体各不相同 /
翼尖装置真的长在翼尖」，`wingIcon.test.js` 守「21 条轮廓两两不重复、都不自交、
翼尖都钉在 6.4、族名与火力对得上、小图和场上同一份数据」，
`palette.test.js` 守色相间距与红区规避。

## 装备：第二槽与僚机编队

机翼回答「怎么打穿 Boss 弱点」，装备回答「怎么活下来、怎么看得爽」。
两条轴刻意正交，`briefing().pick` 永远只推机翼，装备**不进存档**，只在本局内跨关 carry。

| 决定 | 做法 | 为什么 |
| --- | --- | --- |
| 成长轴 | 捡同型号 → **编队数 1→2→3**，换型号重置为 1 | 不叫阶级、不放相位冲击，免得稀释机翼「同频共振」这套身份 |
| Boss 火力 | 僚机弹一律只按 `chip` 结算 | `effectiveDps` / `bossHp` 一行不改，「选错机翼要磨很久」的地基不塌 |
| 主要价值 | 近身消弹圈（照抄铁球范式，蹭掉照样算连消）＋ 编队观赏 | 提升容错，不碰火力配平 |
| 受击 | 僚机**不进 `hitBoxes`**，不吃伤害 | 「带翼更容易被打中」这条教学不能被稀释 |
| 编队形状 | **后置雁形**，横向偏移 ≤ 5.0 格，整体连光晕不越出 12.8 格 | 左右平铺会把刚修好的「看到的宽度 = 判定宽度」原样撑破 |

三型僚机一型一形一色：E1 雁翎（后掠薄板、直射）、E2 梭卫（细长针翼、交替偏射）、
E3 环哨（护环、消弹圈最大）。场上是缩小版乘波体，各有独立炮口闪光、中脊识别灯与拖尾，
新僚机从屏幕外俯冲入列、主机与编队之间拉一道连线光弧；掉在地上的则是**六边形收纳舱**，
和菱形机翼道具一眼分得开。这些全在表现层，判定层只认 `escortsOf(ship)` 那一串坐标。

**替挡与掉命（两条分开的惩罚）**：

- 每次捡到装备（含合流）补一次「替挡」机会。裸机挨致命一击且有编队时，
  **消耗一架僚机**把这一下挡下来，给 1.15 秒无敌；带翼被打中仍只掉翼，
  僚机不是常驻免费护盾，是最后一道防线。
- 替挡机会用完之后再挨一下就是真掉命：**装备掉一级，不清零，复活也不补回满编队**。
  这一版刚补了跨章补给与本章重试，「掉一次命就失去全部投资」会把人推进死亡螺旋。
  掉到 0 才清空；**重试本章**则整槽作废，是更重的一档。

Boss 血量、16 关波次、TTK 断言、`playthrough.test.js` 的阈值一概没动；
机器人测试里也把 `kind: 'gear'` 的道具从「哪只机翼值得捡」的判断里摘出去，
所以它量的仍然只是机翼效率。装备槽为空时所有新分支短路，等价于旧版，随时可回退。

## 进度、容错与战报

16 关一局十几分钟，网页版最怕的不是难，是「关掉就没了」。这一层就是为它补的：

- **进度存档**（localStorage `huanyi-s-jihua:progress`）：只记打到第几关、每关最高星级、
  通关次数，**不记局内状态**——弹幕、血量、机翼阶级一概不存，否则「一命到底」的紧张感
  会被一起存下来。标题页因此多一个「继续 · 第 N 关」和一行存档摘要。
  落点就是上次过掉的那一关；它不是章首（机制上不能选翼）时，自动带上该关的推荐机翼。
- **失败只回本章**：命归零不是回到第 1 关重打十几关，而是「重试第 N 章」——
  回本章第一关、命重置成 3 条、分数退回进本章时的起点（所以重试刷不出新纪录），
  机翼要重新挑一次。暂停面板里也有同一个入口：接个电话不该罚掉前面十几关。
- **跨章补给**：打完一章多一条命，上限 5 条。只加容错、不动敌人强度，
  `bossHp` 那条「推荐机翼 DPS × 目标时长」的反推链一点没碰。
- **战报**：结算与失败面板都给「击落 / 消弹 / 掉翼」三个数，失败还会说
  「Boss 还剩 42% 体力」或「倒在 Boss 出场之前」。玩家该知道自己是怎么输的，
  否则「再试一次」只是一个没有方向的决心。
- **复制战绩**：结算面板一句话带链接，粘到群里就是一次拉新。链接取当前地址，
  所以带 `sharecode` 的分享链天然可用；剪贴板被拒（http、旧 Safari）时把文案摆出来手动复制。
- **首屏只留三句**：手机上一长串说明会把「出击」顶到屏幕外，其余设定收进
  「更多设定与操作」折叠区——第一次打开的人先能找到按钮，再决定要不要读说明书。

存档解析是全防御的：坏 JSON、脏星级、超界关号、隐私模式读不到，一律退回「第一次玩」，
而不是让游戏进不去。这些规则由 `test/progress.test.js` 的 18 条断言守着。

## 发布

`npm run build` 出的 `dist/` 就是完整的静态站点：一个 `index.html`、一份 JS、一份 CSS，
再加 `manifest.webmanifest` 和 `icon.svg`，**没有任何外部请求**（图、字体、音效全部程序生成，
音效由 WebAudio 现场合成）。`vite.config.js` 里 `base: './'` 让所有资源走相对路径，
所以丢到域名根目录、子目录、对象存储的某个前缀下都能直接打开，不必为托管平台改配置。

上线前确认三件事：

1. 浏览器要能创建 **WebGL** 上下文；没有 WebGL 的环境（部分老旧 webview、关掉硬件加速的浏览器）
   起不来，这是 three.js 的硬前提。
2. 音效必须等**第一次用户手势**才解锁——所以「出击」按钮不能省，也不能自动开局。
3. 手机竖屏是主目标：`viewport` 锁了缩放、画布 `touch-action: none`，直接发链接就能玩，
   不需要套壳。HTTPS 且 `manifest.webmanifest` 能正常返回时，PWA 的「加到主屏全屏」也生效。
   带访问授权的分享域可能按「不带 cookie 的 manifest 请求」拦截它并返回 403——
   这只影响「安装到主屏」的名称与图标，JS/CSS 走同源 cookie 正常加载，游戏本体不受影响。

实测过把 `dist/` 挂在 `/game/` 子路径下：五个资源全 200、无 console / exception 报错，
390×844 竖屏下从「出击 → 选翼 → 开局」完整走通，无横向溢出。

## 结构

`src/game/` 与 `huanyi-jihua` 同源，但**已经分叉两处**：机翼表是常规 15 种 + 实验 5 种
（开局选得到 20 种）+ 1 种只能在场上捡到的秘密机翼；进化层换成了「同频共振协议」
（更强的四轴收益、升阶瞬间的相位冲击、满阶后的限时过载）。
机翼表分叉的原因是「换翼要在屏幕上看得出来」：补进来的五种里有三型走**环形护翼**那条路；
进化层分叉的原因见上一节——原来的三阶只是数字变大，玩家看不见「捡到了」。
关卡与 Boss 没动：`levels.js` 16 关波次与 Boss（血量由 `effectiveDps` 算式反推），
`enemies.js`／`boss.js` 行为，`simulation.js` 固定步长状态机，`input.js` 归一化输入，
`random.js` 确定性随机；`rules.js` 多了共鸣冲击、过载与装备道具的几组常量，`wings.js` 多了 `TIERS` 的
设定字段与 `SURGE`，`gear.js` 是新增的第二槽（三型僚机、编队坐标、替挡／掉命降级、chipOnly 弹），
纯数据 + 纯函数。判定层照旧不认识 canvas，也不认识 React。
`test/` 也照抄，包括那个「会躲、会捡翅膀、会按弱点站位」的机器人跑完 16 关的 `playthrough.test.js`。

`src/scene/` 是换掉的那一层：

- `loop.js`：主循环。rAF 是正门，但它会缺席——无头浏览器、内嵌 webview、省电模式都可能
  一帧不给。以前整个循环挂在 rAF 上，rAF 不来连「时间戳不走就退回固定步长」的保险都没机会跑
  （那行保险写在 rAF 回调里），症状是画面停在第 0 帧而面板照样能点。现在：rAF 250ms 不应答
  就判缺席，循环落回 16ms 的 `setTimeout`；缺席期间每半秒仍去敲一次 rAF 的门，它回来就交还。
  调度原语全部可注入，`loop.test.js` 在 node 里用假时钟把「rAF 一帧不给」「时间戳冻在原地」
  「rAF 中途回来」「落后 350ms 只补 0.1s」逐帧排了一遍。
- `view.js`：取景数学与高度表，纯函数，`view.test.js` 守着。
- `palette.js`：四章配色、威胁色、阶级色、21 型机翼的色相与四阶皮、三型装备的亮银皮，
  纯数据，`palette.test.js` 守着。
- `wingIcon.js`：把 `wings.js` 的火力配置换算成形状（一型一条轮廓、一型一件翼尖装置、
  翼弦、炮口位置、炮管长短、招牌零件），纯函数、不碰 three 也不碰 DOM。
  三维机翼和选翼界面的小图都从这里取数，`wingIcon.test.js` 守着「21 条轮廓两两不重复、
  都不自交、翼尖都钉在 6.4」「几路火力就画几根管子」「左右对称」「都落在画框里」。
- `models.js`：程序生成的模型工厂（玄鸟机身与可拆机翼、相位翼场、三型僚机、六边形装备舱、
  六种敌人、Boss、道具、跳关门、各种弹）与对象池。
  **这一份里没有任何文字**，也因此有 `models.test.js` 守着「翼展等于判定用的 12.8 格」
  「带翼明显比裸机宽」「镜像／翻面的部件一律双面」。相位翼场单独导出 `makePhaseFrame()`，
  由渲染层挂到机体上，所以量翼展时它不在那副翼里。
- `stage.js`：相机、灯、天幕、地面栅格、侧栏、岩体、星野、泛光与震屏。
- `render.js`：把状态摆上舞台的总线，外加那层 2D 叠层（飘字、世界锚定的字、闪光、裸机红边、拖动指示）。
  升阶的展开动画、相位翼场逐阶点亮、弹体能量鞘与共鸣冲击环都在这一层，只读 `ship.tier` / `ship.overdrive`。
- `audio.js`／`readout.js`：音效仍全部由 WebAudio 现场合成（`overdrive` 是四层扫频的一记爆发）。
  `readout.js` 集中了全部中文，包括从 `TIERS` 现算收益的 `tierGainLabel()` 与设定名／过载倒计时。

判定层之外还有几份「接线」测试，补的是判定层测试盖不住、而这一版真的栽过的那类失败：

- `wiring.test.js`：把**每个模块都 import 一遍**（重复声明、坏 import、模块作用域的 TDZ 在 `npm test` 就红——
  表现层模块一挂，面板照样能点但世界不动，症状是「黑屏 + 选了机翼没动作」），
  再照 `App.jsx` 的循环在 node 里跑一遍「出击 → 选翼 → 推进 4 秒」，断言世界真的动了。
- `loop.test.js`：主循环的假时钟演习，见上文 `loop.js` 那条。
- `models.test.js`：模型是程序生成的，所以能在 node 里造出来量，见上。

表现层只读模拟状态，一个字段都不写回，所以确定性回放仍然成立：
同一关加同一串输入，模拟结果逐字段一致，判定层的测试不需要浏览器。

**验收表现层只能开浏览器，但有个坑**：无头 Chromium 里原生 `requestAnimationFrame` 实测 **0 帧**
（量帧率那句 `evaluate` 会直接超时），所以拿真实 rAF 截出来的「黑屏」是环境造成的假象。
以前要靠 `addInitScript` 把 rAF 换成手动队列并暴露 `window.__flush(steps, dtMs)`（确定性、快），
或者换成 `setTimeout(16)` 的连续循环（按真实时间推进，能抓到「跑几十帧之后才抛」的错）。
现在这个坑自己填掉了：`loop.js` 在 rAF 缺席时自动落回 `setTimeout`，所以无头环境里
游戏自己就会跑起来——真开浏览器点开页面就能验，上面这一轮的实测截图就是这么来的。
