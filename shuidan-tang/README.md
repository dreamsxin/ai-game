# 水弹堂

手机触屏格子对战。QQ堂式的水弹十字爆流，但这游戏的身份是一条规则：

> **炸中不等于打死。**

爆流把人裹成一颗水泡，水泡自己会挣脱；想真的清掉一个对手，必须在它挣脱之前**再补一发**。
于是每一发水弹都同时是攻击和倒计时——你困住了它，也把自己钉在了它旁边等那 4.2 秒。

```bash
npm run dev:shuidan-tang     # http://127.0.0.1:4194
npm run test:shuidan-tang
npm run build:shuidan-tang
```

## 怎么玩

- 摇杆（屏幕任意处按住拖动）或屏幕方向键走位，键盘 WASD／方向键同样可用。
- 一颗动作键：活着时**放水弹**，被裹成水泡时**猛点挣脱**。这两件事永远不会同时可用，
  而且被困住时玩家的第一反应本来就是猛点那颗按钮。
- 限时内清掉所有对手才算过关。**时间到算输**——不然最优策略会退化成蹲在角落等对手自己炸死。
- 三条命。掉一条命重打本关，重打会换一张新图（箱子和道具的位置都不一样）。

## 四条贯穿全局的规则

1. **两段式击杀**：第一发把人裹成水泡（`BUBBLE_LIFE` 4.2 秒），第二发才算清掉。
   同一片爆流对同一个人只算一次（`blast.hit`），所以补刀必须是真的第二发。
   水泡自己会挣脱，挣脱后有 `GRACE` 1.1 秒无敌——没有这段无敌，人一出泡就会被同一片爆流打回去。
2. **水泡是实体**。堵在巷口就是一面临时的墙：困住对手可能反过来堵住自己的退路。
3. **箱子既是掩体也是装备来源**。加弹／加压／加速／踢弹全藏在箱子里，拆箱这一个动作同时在开路和刷装备。
4. **爆流会连锁引爆**，而且一串弹在同一帧里算成**一片**爆流。所以「多放几发」不是叠伤害，是叠不可控。

## 八关递进的是场地形状，不是数值

`src/game/maps.js` 里每关只有四个旋钮：柱阵排法、箱子密度、对手数量、对手档位。

- 柱阵四种排法：`grid`（经典柱阵，巷子全是单格宽）、`sparse`（缺柱，出现二格宽空场）、
  `lane`（偶数列连成竖墙，只有第 4、8 行横穿）、`hive`（柱子按行错位，最容易被爆流封住）。
- 硬约束只有一条：**奇行奇列必须是空地**。出生角都落在奇/奇上，且出生角的十字五格永远留空，
  所以任何一张图都不会开局就把人埋死。`maps.test.js` 守着这条，还守着「四个出生角永远互相到得了」
  （箱子算可通，因为它们会被拆掉）。
- 箱子和道具由 seed 现场生成：同一关每次开局都是新图，但同一个 seed 一定长出同一张图——
  机器人通关测试靠这条成立。

关卡表：初堂 / 木箱巷 / 双环 / 迷格 / 四方 / 长廊 / 蜂巢 / 终堂，对手 1→3 个，档位 0.35→1。

## 对手：档位是决策质量，不是手脚快慢

`src/game/bots.js` 里的大脑只做三件事，按这个顺序：脚下要炸了吗 → 能不能补刀 → 去拆箱刷装备。
档位（`skill`）不改变移动速度，只改变三件事：

- **反应延迟**：`(1 - skill) * 1.3` 秒才注意到脚下要炸。低档机器人不是走得慢，是慢半拍才开始跑。
- **算不算退路**：放弹前会不会用同一套避难搜索验一遍「这一发下去我还跑不跑得掉」。
  低档按概率跳过这道检查，于是它们会**把自己裹成水泡**——笨该体现在决策上，不该体现在手脚上。
- **挣脱手速**：被困住后连点的频率。

会躲的对手躲得开一发放在它旁边的水弹，只躲不开一发**堵住退路**的。所以大脑里最关键的一段是
`trapped()`：用对手的速度和位置跑一遍同样的避难搜索，找不到安全格才动手。这也是玩家该学会的打法。

危险表（`dangerMap`）会把连锁的提前量传开：被别人的弹带响的那一发按早的引信算。
不传这个提前量，机器人会躲进一个「看起来还有两秒」的格子里，然后被连锁提前炸到。

## 目录

```
src/game/     判定层：没有 DOM、没有 canvas，整局能跑在测试里
  rules.js      场地尺度与常量，blastCells（爆流几何，判定和机器人共用）
  maps.js       关卡表、柱阵排法、seed 建图、连通性检查
  simulation.js 走位、放弹、踢弹、连锁引爆、两段式击杀、过关判定
  bots.js       机器人大脑（危险表 / 避难搜索 / 开火位 / 封死判定）
  input.js      键盘、屏幕方向键、拖动摇杆归一成 {dir, bomb, struggle}
src/scene/    表现层：只读状态，画错永远不影响判定
  render.js     Canvas 2D
  audio.js      程序化音效（WebAudio 现场合成，无音频文件）+ 触觉反馈
  readout.js    面板文案（纯函数，可单测）
```

`step(state, input, dt)` 是**原地推进**的：一局里每帧都克隆一张 11×13 的图和四个角色，
在手机上是白扔的开销。代价是 React 那边必须给出一个新外壳（`setView({ ...gameRef.current })`），
否则 setState 会因为引用没变而整帧跳过——画面在动而 HUD 上的时间永远停在开局那一刻。

`input` 也可以传一个数组，按 id 逐个指定每个角色的输入。测试要冻住某个对手、
或者让同一个大脑同时接管四个人时走这条，判定层因此不需要任何测试专用开关。

## 音效：说的是处境，不是动作

两对声音必须一听就分得开，因为它们对应的处境正好相反：

- `bubbleFoe`（往上滑）与 `bubbleSelf`（往下沉）——「我困住了人」和「我被困住了」。
  这两件事在画面上长得几乎一样（都是一颗水泡），声音是唯一能立刻分开它们的通道。
- `popFoe` 与 `popSelf`——清场和丢命不该是同一声。

`blast` 的音高跟着连锁数爬（连锁是这游戏里唯一会失控的东西）。别人放弹、别人捡道具不出声：
一局四个人，每个动作都出声会糊成一片。

## 测试

```bash
npm run test:shuidan-tang
```

- `simulation.test.js`：两段式击杀、水泡是实体、连锁一次算完、踢弹、时间到算输、暂停。
- `maps.test.js`：四个出生角互通、出生区留空、奇行奇列不立柱、道具只藏在箱子里、难度曲线不倒挂。
- `bots.test.js`：危险表与连锁提前量、会躲、反应延迟随档位、没退路不放弹、会补刀。
- `playthrough.test.js`：满档大脑接管玩家跑完八关，守「每关都过得去」「清场靠补刀不是熬时间」
  「同一张图换低档对手就明显好打」「低档会把自己裹成水泡」。
- `audio.test.js` / `readout.test.js` / `input.test.js`：声音的处境语义、提示的优先级、
  四向折算与动作键的脉冲语义。
