# 中国城市生成器 · China City

参数化的三维城市生成器。五种风格各是一座能一眼认出来的中国城市，同一个种子永远生成同一座城，
换种子就换一座。不是游戏，没有目标 —— 拖参数看城市实时长出来就是全部玩法。

```bash
npm run dev:zhongguo-chengshi     # http://127.0.0.1:4184
npm run test:zhongguo-chengshi
npm run build:zhongguo-chengshi
```

## 五种风格，靠拉开差距而不是换配色

`src/city/styles.js` 是纯数据的「配方表」。关键在于每一栏都拉开差距：色板、地形、路网形态、
天际线、特色构筑物、建筑形态权重。只换颜色的话五座城会长得一模一样。

- **重庆 8D 魔幻** — 118 米高差、依山台地、两江汇流；层叠立交（3 层以上）、轻轨穿楼、
  过江索道、跨江大桥、山城步道。建筑以板式住宅 + 瓷砖老楼 + 吊脚楼为主。
- **上海陆家嘴** — 三角洲几乎没高差（relief 7）、江湾；玻璃幕墙塔楼和裙楼塔楼占七成，
  地标 600 米。环形放射路网。
- **古都西安** — 棋盘里坊、护城河、**完整方形城墙 + 城门楼**；限高 64 米，合院和大屋顶殿宇为主，
  青灰瓦顶。
- **赛博深圳** — 超级街区、入夜、霓虹拉满；带冠顶超高层 + 玻璃塔，五个地标，
  高架轨道穿行。
- **杭州江南水乡** — 密水网 + 五座拱桥 + 水巷；白墙黑瓦民居占五成四，限高 46 米，
  平均高度 11 米。

`KINDS` 有十一种建筑形态，渲染层按 `kind` 造完全不同的体块 —— 所以权重表决定的是城市的「长相」，
不是它的调色。

## 结构参数和外观参数是两条通路

这是这个项目最要紧的一个工程决定。参数分两类，`src/city/params.js` 的 `STRUCTURAL` 集合划线：

- **结构参数**（规模、密度、街区尺度、路网、分区、天际线、地形、特色构筑物）一改就要重算整座城，
  重建几何。`App.jsx` 把这些 key 序列化成一个「结构指纹」，只有指纹变了才重新 `generateCity`，
  而且再 debounce 70ms —— 否则拖一下滑块就是几十次全量重建。
- **外观参数**（光照时段、亮度、雾霾、霓虹）只走 `applyAppearance`，改材质和灯光，不动几何。

这条线划错的后果是静默的：新加一个滑块却忘了把 key 放进 `STRUCTURAL`，它就既不触发重建、
也不在外观那条依赖里，**拖动完全没反应**，看起来只像「这个参数好像没什么用」。
`test/params.test.js` 把两条通路的并集钉成控件全集，并且不许重叠（重叠等于每次都白重建一次）。

## 生成顺序是有依赖的

`generateCity` 里的次序不能随便换：

1. `createTerrain` 先出地形；
2. `planFeatures` 定水巷、城墙、立交 —— **水巷会把河道刻进地形**，所以它必须在路网之前；
3. `buildRoads` 出路网，再 `clipLinesToLand` 把伸进水里的路段剪掉，然后栅格化；
4. `plan.stampBlockers(raster)` 把城墙／水巷占掉的格子打上禁建标记；
5. `placeBuildings` 才在剩下的地方放楼 —— 它看到的是刻过河道、剪过路网、盖过禁建的那份地形；
6. `finishFeatures` 最后补桥、索道、高架、轻轨穿楼（这些要知道楼在哪）。

「建筑不会落到水里」是靠这个顺序保证的，不是靠事后筛。`test/city.test.js` 逐个风格核 `base < 1`
的楼数必须是 0。

## 同种子同城市

`src/city/random.js` 是种子化的，`seed` 拼上风格 id（`${params.seed}|${style.id}`）之后
再派生出 `:features`、`:props` 等子流。所以换风格不会只是换配色 —— 随机流本身也变了。
同一份参数跑两次，`stats` 除 `genMs` 之外必须逐字段相同。

## 统计口径

`stats` 里除了建筑数、总层数、最高楼、最高点、地形高差、路网公里数，还有几个是「特色兑现了没有」
的体检项：`interchangeLevels`（立交最多几层）、`monorailPierced`（真的穿了几栋楼）、
`cableCars`／`bridges`／`viaducts`。测试直接核这些数 —— 「重庆有没有重庆味」不能靠肉眼。

`population` 是 `总层数 × 26` 估的，纯装饰，别当数据用。

## 测试

16 个测试，`node --test test/*.test.js`：

- `city.test.js` 核生成结果：五种风格都出得来、同种子同城市、换种子换城、
  重庆的高差／立交／穿楼／索道都到位、风格之间的天际线差异够明显（陆家嘴该比西安高三倍以上，
  西安和杭州的限高不能失效）、参数真的生效、开关能覆盖预设、没有楼泡在水里。
- `params.test.js` 核参数面板本身：每个控件都在两条通路之一（漏了就是拖了没反应）、
  滑块默认值不越界、下拉默认值在选项里、分区比例归一化、每种风格用自带默认值就能直接生成。

## 还没做的

- 没有音效。生成器只有「重算一次」这一个事件，加一记点击声是装饰，不是反馈 —— 等它变成
  有目标的玩法再说。
- 建筑内部、室内、人流车流都没有；`props` 只有街灯和行道树，贴着 level ≥ 2 的干道放，
  夜景全靠它们把路网点出来。
